# antislop audit 001 (2026-10-04)

Mode: after (session override). Scope: the two web UIs (admin panel `sigap/static/admin/`, student portal
`sigap/static/student/`) and the text the Telegram bot and sign-in email show to students.
Priority follows the rule tier: Hard Gate = HIGH, Purpose-Gate = MEDIUM, Quality Locks = LOW.
Nothing has been changed. Reply with the numbers to fix.

How it was checked: read every UI file; ran the antislop contrast checker on each colour pair in both themes;
drove both UIs in headless Chromium at 375 px in light and dark mode (all 9 admin routes and the student login),
measuring page overflow, tap-target sizes, keyboard focus and console errors.

## HIGH (Hard Gate)

1. **R-36 / R-38: the privacy notice names the wrong AI provider.** `student/app.js:55` tells students their
   messages go to "Google Gemini", but the agent now runs on DeepSeek through an OpenAI-compatible endpoint.
   Students consent to a statement that is false. Fix: name the provider the flow actually uses (ideally filled
   from config so it cannot drift again) and bump `CONSENT_VERSION` so students re-consent to the corrected text.

2. **R-38: invented contact address presented as real.** The privacy notice gives `layanan.akademik@und.ac.id`
   for data requests (`student/app.js:59`). The demo label at line 60 only says the *student data* is synthetic.
   Fix: mark the address as a demo placeholder, or replace it with a real one.

3. **R-32: ticket and student rows only open with a mouse.** Inbox rows (`admin/app.js:136`) and student rows
   (`admin/app.js:244`) are `<tr onclick>` with no focusable control, so a keyboard user cannot open a ticket
   (the panel's main job) or edit a student. Fix: put a real button or link in each row, or make the row
   focusable with Enter/Space handling.

4. **R-32: the hidden mobile menu traps keyboard focus.** Below 720 px the closed nav slides off-screen but stays
   in the tab order: in the test, the first 6 Tab presses all landed on invisible nav links. The menu button
   has no `aria-expanded`, Escape does not close the menu, and focus does not move into it when opened
   (`admin/app.css:215`, `admin/app.js:100`). Fix: `inert` or `visibility:hidden` on the closed nav,
   `aria-expanded` on the button, Escape to close, focus into the menu on open and back to the button on close.

5. **R-32: the focus indicator on inputs is close to invisible.** Focused inputs get an outline in
   `--accent-soft`, which is 1.17:1 against the surface in light mode and 1.19:1 in dark mode, so only the 1 px
   border colour change shows focus (`admin/app.css:87`). Input borders themselves are 1.33:1 (light) and
   1.29:1 (dark), below the 3:1 non-text minimum, so empty fields barely read as fields. Fix: a 2 px
   `:focus-visible` ring in `--accent`, and a darker border token for inputs.

6. **R-25: four text pairs fail WCAG AA in light mode** (all dark-mode pairs pass):
   - "Terbuka" badge and the student-portal warning box, `#b45309` on `#fdf0dc`: 4.47:1
   - "Telegram"/"Dijawab"/"aktif" badges, `#15803d` on `#e3f4e8`: 4.39:1
   - table headers, `#6b6e66` on `#f0eee8`: 4.47:1

   Fix: darken `--warn`, `--good` and `--muted` one step in the light theme; re-run the checker.

7. **R-03: almost every control is under the 44 px tap target on a phone.** Measured at 375 px: small buttons
   are 29 px (menu ☰, Sinkronkan, inbox tabs, Ubah, Undangan, Lihat, Reset), regular buttons 36 px, inputs
   35 to 38 px, the "Lihat sebagai tabel" toggle 19 px. On the phone-first student portal, the sign-in field
   is 35 px and the main button 39 px. Fix: a 44 px minimum on touch screens (`@media (pointer: coarse)`),
   which keeps the dense desktop layout.

8. **R-27: student portal actions fail silently.** Unlinking a chat, revoking a token, requesting data deletion
   and signing out (`student/app.js:110-127`) have no error handling, so a failed request shows nothing. Also,
   `boot()` (`student/app.js:131`) treats any `/me` failure, including a server error or lost connection, as
   "not signed in" and shows the login form. Fix: catch and show the error on each action; show the login form
   only on 401 and an error state otherwise.

9. **R-02: em dashes in text students and staff read.** 25 strings:
   - student portal: `student/app.js:55, 58, 85, 115`
   - admin test chat deadline bubble: `admin/app.js:418`
   - bot replies: `sigap/agent.py:145, 147, 387, 426, 428`; `sigap/tools.py:151, 152, 156, 231, 233, 244, 247,
     310, 312` (deadline lists, window status, handbook citations)
   - calendar event titles: `sigap/tools.py:510, 513`
   - tool-to-model text: `sigap/tools.py:613, 617`
   - Telegram tool trace: `sigap/telegram_bot.py:89`; sign-in email signature: `sigap/student_api.py:89`

   Fix: replace each with a comma, colon, period or parentheses. Code comments are out of scope.

10. **R-37 (with R-31, R-06): no design direction is written down.** There is no `DESIGN.md`. The current look
    (Plus Jakarta Sans, warm off-white with a teal accent, JetBrains Mono for codes) was chosen by the agent
    without a brief from you, and the UI was never labelled a draft. Some choices have good reasons that only
    need writing down (Plus Jakarta Sans is an Indonesian typeface from Jakarta; a monospace font keeps NIMs,
    reference numbers, tokens and the 6-digit code aligned), but none are recorded. Fix: you answer a few
    direction questions (identity, mood, palette, type) and I transcribe them into `DESIGN.md` with the
    ENERGY / RHYTHM / MOTION dials; I do not invent the content.

## MEDIUM (Purpose-Gate)

11. **R-04: emoji used as decoration in the web UI.** Every admin nav item carries one
    (📥 📊 🎓 📅 🗓️ 📖 👥 💬 🔑, `admin/app.js:62-70`); error toasts start with ⚠️ (`admin/app.js:36`); the inbox
    detail uses 🎓 (`:146`); test-chat bubbles use 📅 📖 🔧; the student portal uses 🔗, ⚠️, a 42 px ✅ and 💬
    (`student/app.js:26, 75, 84, 102`). In the web panel these add colour noise without information. Fix:
    remove them, or use one consistent icon set with a written reason. (Emoji in Telegram messages, such as ⏰
    and 📨 marking a reminder or a handoff, act as message-type markers in a chat; flag them for your decision
    rather than removal.)

## LOW (Quality Locks and craftsmanship)

12. **C-4: on phones, sync status is shown by colour alone.** Below 720 px the "Langflow: …" text is hidden and
    only a green or red dot remains (`admin/app.css:220`, `admin/app.js:113`). Fix: keep a short text label or
    an icon with an accessible name.

13. **C-3: internal tool names appear in the student's chat.** Each bot reply ends with a trace like
    "🔧 answer_campus_policy (NOT_FOUND) · … via langflow" (`sigap/telegram_bot.py:89`). Useful for the demo
    video and judges, but noise for a student. Fix: show it only in the admin test chat, or behind a setting.

14. **R-03: mobile layout leftovers.** The closed nav's 1 px border and a few fragments peek at the left
    edge at 375 px. On the Students table, the "Undangan" button sits off-screen inside the horizontal table
    scroll. Fix: hide the closed nav completely (also fixes part of #4); give the student list a stacked
    layout on phones.

15. **R-27 (quality): empty states say "nothing here" but not what to do.** For example "Belum ada item."
    (schedule), "Tidak ada tiket di sini." (inbox) and "Belum ada data." (dashboard). Fix: say why it is empty
    and give the one action that fills it, e.g. "Belum ada tenggat untuk mata kuliah ini. Tambah lewat
    + Tambah tenggat/ujian."

## Checked and passing

- No horizontal page overflow at 375 px on any of the 9 admin routes or the student login, in light or dark mode.
- No JavaScript errors in either theme.
- Every dark-mode colour pair passes AA; dark mode is chosen from the system setting.
- No gradients, glassmorphism, glow, background grids or decorative illustrations; shadows are a 1 px hairline.
- Dashboard numbers come from the database; no invented statistics, testimonials or logos.
- The chart has a "view as table" alternative; dialogs are native `<dialog>` and close with Escape.
- Every nav item leads to a real view; no dead buttons were found.
- Demo data is labelled synthetic in the privacy notice.
